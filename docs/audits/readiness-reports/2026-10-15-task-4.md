## Bounded source change

- `cryptoVault.ts`: added a seven-line `captureWebVaultLifetime()` guard producer. It captures the active master-key object identity and account scope, and reports whether both remain current. It does not expose key material, create a key copy, introduce runtime/session objects, change namespace derivation, or alter lock/unlock behavior. Existing lock zeroizes the captured old key, and every unlock installs a different key object, so same-account reopen invalidates the old guard.
- `AppWorkspace.svelte`: captures the vault guard plus username/endpoint at admission, together with a component destruction flag. Checks occur after the local tail wait, on entry to the acquired Web Lock before vault reload, and after the awaited reload before assigning materialization or invoking the captured user operation. Thus obsolete queued work cannot adopt a newly active account merely because the lock becomes available later. The existing promise tail, cross-tab lock and user operation/dependency closure remain intact.
- Late initial hydration checks the same captured lifetime before assigning state or reporting a hydration error. Its `finally` registers manual sync/starts auto sync only if that lifetime is still current. `onDestroy` invalidates the component before stopping scheduling, so a pending initial read cannot revive the destroyed controller.
- `browser-durability.spec.ts`: added the two regressions described above. Bob's materialized items, operation states and outbox must remain empty after pending-switch cancellation. Alice's previously acknowledged state and exact outbox are checked unchanged after switching back. Same-account reopen must not persist the obsolete pending task.

This is a guard for admitted queued work and the asynchronous committed-state/initial-hydration reload boundaries identified by R05. It is not a new general cancellation/runtime architecture. No native, auth refresh, protocol, generated WASM/FRB, dependency, fixture bundler or synthetic shell file changed in this round.
