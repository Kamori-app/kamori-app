## Proven defect and RED → GREEN

Existing UI says every write needs exact typed confirmation and fresh passkey/TOTP; server `apps/cloud-server/src/features/admin/services.rs:700` already rejects confirmation other than `SET <key>`. Before the fix, clicking Apply with empty confirmation still initiated a fresh ceremony and sent the privileged HTTP request. A permissive synthetic response made that client request observable as a success notice; it does not establish that the actual backend accepted the request.

Minimal product fix: three lines in `updateSetting` reject `settingConfirmation !== `SET ${setting.key}`` before reauthentication. With the fix, the same blank-confirmation interaction produces a visible error, zero reauth calls and zero privileged POSTs.
