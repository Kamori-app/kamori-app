## Root cause and implementation

The auth `setup_test_app`, admin/invites/operations `test_pool`, and operations
`admission_database` helpers returned `Option`. Their callers returned normally
when neither database variable existed, which libtest counted as passed tests.

Extended the existing `platform/test_support.rs`; existing `test_config` and
`test_state` remain intact. Shared test-only `required_test_database_url() ->
String` selects nonempty `KAMORI_DATABASE_URL`, then nonempty `DATABASE_URL`.
Empty/whitespace-only inputs count as missing. Missing values panic with an
actionable dedicated PostgreSQL prerequisite and README location, without URL
values. Pure resolver tests cover explicit precedence, fallback, absent, empty,
and whitespace inputs. No process-global environment mutation occurs in tests.

Removed Option/early-return skips from all current database test helpers and
callers, including operations lock regressions. Additional operation pool
connections use the same resolver. Existing migrations, migration OnceCell,
UUID fixtures, search_path/schema isolation, lock staging, pool options and
cleanup behavior are preserved.

The subprocess regression executes the actual existing admin passkey lifecycle
integration test with `--exact` and both database variables removed only from
the child process. It asserts `running 1 test`, the expected test name, a
nonzero exit and actionable prerequisite diagnostics. It cannot pass after a
rename accidentally selects zero tests.

## Boundary finding and minimal change

Turbo 2.10.11 uses strict env mode. The previous generic `test` task provided no
DB passthrough, so root `bun run test`/`bun run verify` dropped a supplied DB URL
before cloud-server tests. Generic test caching could also replay old success
rather than execute against the current external DB state.

Only these files changed in this fix commit:

- `turbo.json`: scoped `cloud-server#test` override preserves `dependsOn:
  ["^test"]`, sets `cache: false`, and allows `KAMORI_DATABASE_URL` and
  `DATABASE_URL` through strict env using `passThroughEnv`.
- `apps/cloud-server/README.md`: documents scoped DB passthrough, mandatory real
  repeated execution, other packages retaining their test caching, and the
  concrete root command `bun run test --filter=cloud-server`.

Generic task configuration and other package overrides remain unchanged. No
runtime code, dependency, toolchain, global env configuration, shell script,
workflow or database migration was changed. The pinned rust-toolchain.toml
1.97.1 works through the existing PATH; no broad environment passthrough was
added. Database URLs are not logged by this change.
