# Решения продолжения аудита

Архив решений нового плана [release-readiness](../superpowers/plans/2026-10-15-release-readiness.md) в порядке принятия. Предыдущие пятнадцать решений сохранены отдельно в [исходном архиве](2026-10-15-decisions.md).

| № | Решение и основание | Цена ошибки / ограничение |
|---|---|---|
| 1 | Продолжать в выбранной пользователем `fix/audit-remediation`, без нового worktree и новых `codex/` веток: пользователь явно исправил место доставки изменений | Общий checkout требует последовательной реализации, чистых base/head и исключения чужих незавершённых файлов из коммитов |
| 2 | Выполнить принятые шесть категорий оставшейся работы как восемь ограниченных задач проверки существующих контрактов и исправлять воспроизведённые нарушения | Новые сценарии могут выявить дополнительные ошибки; выполнение набора не сертифицирует все release paths |
| 3 | Использовать unsigned device build и установленный iOS26.2 simulator с SDK27, не выдавая их за физический запуск/доставку scheduler/подпись | Ошибки аппаратного устройства, power loss и distribution остаются возможными и требуют внешних испытаний |
| 4 | Выполнить конечную локальную нагрузку и настоящий disposable encrypted PITR/blob restore без придуманного production SLA | Реальная ёмкость и ошибки удалённых провайдеров могут отличаться от локального окружения |
| 5 | PITR выполнять на PostgreSQL16 по hosted provisioning/runbook, application/CI tests — на PostgreSQL18: физические backup/WAL требуют совпадения major | PostgreSQL18 operational upgrade потребует отдельного restore exercise; provenance двух контуров должна быть явной |
| 6 | Для Dart hook, удаляющего DEVELOPER_DIR, использовать узкий scoped xcrun runner с абсолютным /usr/bin/xcrun и сохранением аргументов/exit code | При текущем глобальном выборе CommandLineTools wrapper необходим; успешная сборка не объявляется успехом plain unwrapped команды |
| 7 | Включить минимальное исправление native Contacts adapter в Task1 после настоящего production RED при внешнем удалении копии | ID-filtered lookup может иметь платформенные/нагрузочные отличия; provider/permission ошибки должны сохраняться, новые permission prompts недопустимы |
| 8 | Разрешить минимальное исправление AppWorkspace в Task4 только после настоящего multi-tab UI RED: tab-local materialization входит в проверяемую durability границу | Изменение общего UI state может затронуть single-tab/offline/account switch; нужны реальные две вкладки, isolation controls и web gates |
| 9 | Повторно открыть Task2 для узкого исправления Turbo после активного Task4: strict env удаляет заданный DB URL, настоящий single-test запуск это подтвердил; DB gate не должен заменяться cached success | Серверным тестам нужна живая отдельная БД; отключение кеширования увеличит частоту запусков, последовательное исправление добавит время |
