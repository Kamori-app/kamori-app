# Решения продолжения аудита

Архив решений нового плана [release-readiness](../superpowers/plans/2026-10-15-release-readiness.md) в порядке принятия. Предыдущие пятнадцать решений сохранены отдельно в [исходном архиве](2026-10-15-decisions.md).

| № | Решение и основание | Цена ошибки / ограничение |
|---|---|---|
| 1 | Продолжать в выбранной пользователем `fix/audit-remediation`, без нового worktree и новых `codex/` веток: пользователь явно исправил место доставки изменений | Общий checkout требует последовательной реализации, чистых base/head и исключения чужих незавершённых файлов из коммитов |
| 2 | Выполнить принятые шесть категорий оставшейся работы как восемь ограниченных задач проверки существующих контрактов и исправлять воспроизведённые нарушения | Новые сценарии могут выявить дополнительные ошибки; выполнение набора не сертифицирует все release paths |
| 3 | Использовать unsigned device build и установленный iOS26.2 simulator с SDK27, не выдавая их за физический запуск/доставку scheduler/подпись | Ошибки аппаратного устройства, power loss и distribution остаются возможными и требуют внешних испытаний |
| 4 | Выполнить конечную локальную нагрузку и настоящий disposable encrypted PITR/blob restore без придуманного production SLA | Реальная ёмкость и ошибки удалённых провайдеров могут отличаться от локального окружения |
| 5 | PITR выполнять на PostgreSQL16 по hosted provisioning/runbook, application/CI tests — на PostgreSQL18: физические backup/WAL требуют совпадения major | PostgreSQL18 operational upgrade потребует отдельного restore exercise; provenance двух контуров должна быть явной |
| 6 | Для Dart hook, удаляющего DEVELOPER_DIR, использовать узкий scoped xcrun runner с абсолютным /usr/bin/xcrun и сохранением аргументов/exit code | При текущем глобальном выборе CommandLineTools wrapper необходим; успешная сборка не объявляется успехом plain unwrapped команды |
| 7 | Включить минимальное исправление native Contacts adapter в Task1 после настоящего production RED при внешнем удалении копии | ID-filtered lookup может иметь платформенные/нагрузочные отличия; provider/permission ошибки должны сохраняться, новые permission prompts недопустимы |
| 8 | Разрешить минимальное исправление AppWorkspace в Task4 только после настоящего multi-tab UI RED: tab-local materialization входит в проверяемую durability границу | Изменение общего UI state может затронуть single-tab/offline/account switch; нужны реальные две вкладки, isolation controls и web gates |
| 9 | Повторно открыть Task2 для узкого исправления Turbo после активного Task4: strict env удаляет заданный DB URL, настоящий single-test запуск это подтвердил; DB gate не должен заменяться cached success | Серверным тестам нужна живая отдельная БД; отключение кеширования увеличит частоту запусков, последовательное исправление добавит время |
| 10 | Сохранить desktop UX по README: sharing остаётся web/mobile; Task5 проверяет TTL в настоящем web sharing component с отдельным обозначением | Desktop sharing UI не появится; дополнительные web fixture/component inputs должны учитываться в UI test gate и его cache |
| 11 | Исправить отображение импортированных EXDATE/RDATE/detached overrides как существующую calendar correctness; расширить Task6 минимальными shared read-model metadata/web/mobile plumbing и необходимой генерацией bindings | Больше межклиентских изменений, regeneration/WASM и свежих native builds; риск regressions выше. Advanced editor/auth/cloud protocol/time policy не расширяются |
| 12 | Использовать существующие PimValue::Records для read-only recurrence metadata и typed native view vectors/occurrence records; raw iCalendar остаётся authoritative, series identity сохраняется | Rust/JS/native mapping может разойтись; нужны shared typed corpus, binding verification и preservation при series edit. Unsupported RFC forms нельзя молча отображать неверно |
| 13 | Сохранить Agenda по SPEC и использовать существующее anchor/weekDays окно7дней с недельной навигацией, actual occurrences и deduplication | Вместо прежнего списка всех серий появляется конечная неделя occurrences; нужны date-window/override/multiday tests и переходы между неделями |
| 14 | Для opt-in системной Calendar projection неподдерживаемых provider API recurrence sets использовать явный отказ и удалить только ранее mapped OS-копию, сохранив mapping/error/permission contract: RRULE без исключений показывал бы неверные события | Корректные импортированные наборы с исключениями не проецируются в OS до поддержки provider; нужны cleanup/persistence/failure tests, данные и first-party display остаются доступны |
| 15 | Включить actual end в mobile interval и series-label для RDATE-only delete в текущий compliance fix: оба требования прямо заданы brief, хотя review оценил UI-влияние как Minor | Небольшое расширение UI diff и mounted assertions продлевает исправление; advanced authoring и time policy не меняются |
| 16 | После независимого reconciliation коллекций возвращать исходную provider/storage ошибку со stack, а при её отсутствии — постоянный recurrence refusal; сохранить действующий error contract без нового публичного aggregate type | Одновременные ошибки показываются по одной за запуск; оставшийся отказ может стать виден на следующем retry. Нужны mixed-failure и cleanup-recovery controls |
| 17 | Исправить timed DTEND duration через разность реальных instants, all-day через civil axis, а TZDateTime нормализовать в обычный UTC DateTime до viewer conversion: actual RED и RFC5545 подтверждают существующий контракт | Меняется поведение DST-edge duration/display; нужны exact start/end и viewer-timezone controls. DURATION authoring, API и bindings не расширяются |
| 18 | Перестроить старый combined late-invite/ownership test: реальный redeem+offer до удаления, затем оба production accept_offer/delete порядка; отдельные real tests доказывают оба порядка membership admission | Один прежний combined schedule разделяется; все owner/usage/deletion asserts и новые точные913 blocker/member asserts должны сохраниться. Raw INSERT не заменяет redeem |
| 19 | Включить наблюдение об очистке частично созданного container в тот же раунд Task8, что и Important endpoint defect: пользователь требует исправить все подтверждённые дефекты, ownership cleanup обязателен | Дополнительный реальный failed-start schedule и adapter tests увеличивают время; удаляются только точные owned resources после проверки labels, без общей engine abstraction |
| 20 | Включить новую critical in-flight account-isolation регрессию в существующий acceptance @smoke; сохранить прежнее smoke/full разделение остальных9 durability cases | PR получает дополнительный mounted browser сценарий и время выполнения; CI selection/browser inputs должны его поддерживать, новый test framework и общая смена policy не нужны |
| 21 | Закрыть новый Minor N1 из scoped final review коротким follow-up исходного исполнителя: три catch-обработчика обходят lifetime guard уведомлений; пользователь явно требует исправить всё | Дополнительные focused UI RED/GREEN, исправление3 handlers, scoped review и новый fresh full acceptance увеличат время; повторный whole-review/редизайн/посторонние изменения не нужны |

[Дословные21 rulings](readiness-reports/2026-10-15-rulings.md) сохранены до удаления scratch; номера и порядок совпадают с исходным ledger.
