# Аудит кода и бизнес логики Kamori

Дата: 15 октября 2026. Исходный коммит: `8124892`. Область: весь монорепозиторий; сервер, криптографическое ядро, DAV и desktop, web и admin, Flutter, инфраструктура и CI. Контракт: `AGENTS.md` и `SPEC.md`.

Базовые тесты проходят, однако не проверяют ряд важных сценариев: завершение входа после смены пароля, потерю ответа при принятии приглашения, конкурентные записи с разными идентификаторами, редактирование и повторение событий в разных часовых поясах, восстановление desktop после прерванного обновления токена и фоновую системную проекцию. Найденные дефекты перечислены ниже; статус каждого будет обновлён после регрессионных тестов и отдельного ревью.

Это внутренний аудит исходного кода и тестов. Он не заменяет независимый аудит безопасности или испытания на физических устройствах.

## Метод и исходные проверки

- Проверены реализация и фактические утверждения тестов относительно `SPEC.md`; планы из roadmap не считались отсутствующей функциональностью.
- Дефекты разделены на воспроизведённые вызовом реального кода и подтверждённые трассировкой. Перед исправлением каждой ошибки нужен регрессионный тест, показывающий исходный сбой.
- Изолированная PostgreSQL 18 с синтетическими данными запущена только на loopback. Production, пользовательские данные и реальные секреты не использовались.
- CI уже предоставляет PostgreSQL для Rust-тестов. Локально 13 серверных интеграционных тестов молча возвращают успех без URL БД; поэтому отдельно выполнен настоящий запуск с БД.

Существующие сильные стороны: серверные MessagePack round-trip явно проверяют UUID strings и binary bytes; операции имеют подписи, server-side role/epoch проверки и уникальные идентификаторы; recovery уже имеет durable idempotency; локальные materialization/outbox сохраняются до upload; системная проекция выключена по умолчанию.

Дополнительные пробелы без подтверждённой ошибки: полный WebAuthn/admin flow; multi-tab IndexedDB и crash durability; rotation rollback/coverage/quarantine; egress reservations при abort/crash и временных границах; Valkey против in-memory store; импортированные EXDATE/RDATE/recurrence exceptions; системные контакты/календарь на реальных Android/iOS. Они требуют отдельных интеграционных сценариев и внешних release exercises. Исправление найденных 19 дефектов само по себе не закрывает эти release gates.
